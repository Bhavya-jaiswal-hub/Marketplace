Notification Entity

# Overview

The Notification entity stores notifications generated by the marketplace for users.

Notifications keep customers, sellers, and administrators informed about important events such as order updates, payment updates, return requests, refunds, seller verification, and other marketplace activities.

# Purposev

Store user notifications.
Inform users about important marketplace events.
Track whether a notification has been read.
Associate notifications with relevant business operations.
Support in-app notification history.
Provide a foundation for future notification channels.

# Validation Rules 

Every Notification must belong to a valid User.
Notification Type is mandatory.
Title is mandatory.
Message is mandatory.
Notification Type must contain a valid type.
Is Read must contain a valid boolean value.
Read At must be provided when the notification is marked as read.
Reference ID must be valid when the notification is associated with a business operation.
A user can access only their own notifications.
Invalid or unauthorized notification operations must be rejected.

# Business Rules

Notifications are generated when relevant marketplace events occur.
A notification must be associated with the User who should receive it.
Notifications related to orders must reference the relevant Order or Order Item when applicable.
Notifications related to payments must reference the relevant Payment Transaction when applicable.
Notifications related to returns or refunds must reference the relevant business record when applicable.
A user can mark their own notifications as read.
A user cannot modify or mark another user's notifications as read.
Reading a notification must not change the underlying business operation.
Notifications should preserve their original message and event context.
The Super Admin may receive notifications related to administrative operations.
Notifications may be retained as historical records according to marketplace retention rules.
Notification delivery failure must not modify or roll back the underlying business transaction.
Future notification channels such as email, SMS, or push notifications may use the Notification entity as their source.
